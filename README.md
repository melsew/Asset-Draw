# Asset-Draw Runnable Starter MVP

A clean starter for the Asset-Draw promotional prize-draw platform.

## Stack
- React + TypeScript + Vite
- FastAPI + Python
- PostgreSQL-ready Docker environment
- Redis-ready Docker environment

## Current status
The repository includes a Render Blueprint for a **public demo**, not a production prize-draw service.
Demo campaigns, OTP, entries, and draw results are sample/simulated flows. No SMS is sent and no real
payment, entry, or draw is processed. Do not collect real participant data on this deployment.

## Run backend
```powershell
cd backend
python -m venv .venv
.venv\\Scripts\\activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```
API: http://localhost:8000/docs

## Bootstrap the first owner account
The first staff SUPER_ADMIN is created once from the backend directory after PostgreSQL is running and the
database is migrated. This does not promote a participant phone account. Configure stable, private
`AUTH_SECRET_KEY` and `AUTH_ENCRYPTION_KEY` values in the ignored local `.env` file before bootstrapping.
Keep those keys stable: changing them invalidates tokens and prevents decrypting existing staff MFA secrets.
When running the backend directly on the host alongside Docker services, the ignored `.env` must use
`localhost:5433` for PostgreSQL and `localhost:6379` for Redis; the `postgres` and `redis` hostnames are
only available inside the Compose network.

Run the one-time bootstrap from PowerShell. The password is entered through a secure prompt and is not saved
in shell history:

```powershell
cd backend
$env:DATABASE_URL = "postgresql+psycopg://asset_draw:asset_draw@localhost:5433/asset_draw"
$env:REDIS_URL = "redis://localhost:6379/0"
$env:BOOTSTRAP_ADMIN_EMAIL = Read-Host "Owner staff email"
$password = Read-Host "Owner staff password" -AsSecureString
$env:BOOTSTRAP_ADMIN_PASSWORD = [Net.NetworkCredential]::new("", $password).Password
python -m app.auth.bootstrap_admin
Remove-Item Env:BOOTSTRAP_ADMIN_EMAIL, Env:BOOTSTRAP_ADMIN_PASSWORD, Env:DATABASE_URL, Env:REDIS_URL
```

The command prints a one-time TOTP enrollment URI and setup token. Keep both private, add the URI to an
authenticator app, and finish MFA enrollment at `http://localhost:5173/staff/setup` within 10 minutes.
Then sign in at `http://localhost:5173/staff/login` with the staff email, password, and current authenticator
code. The admin dashboard is at `http://localhost:5173/admin`. Bootstrap refuses to run if a SUPER_ADMIN
already exists.

## Deploy the public demo to Render
1. Push this repository to a Git provider supported by Render and create a Render account.
2. In Render, choose **New > Blueprint**, connect the repository, and deploy `render.yaml`.
3. The Blueprint creates a web service, PostgreSQL database, and Redis instance. Review Render's current
   prices before confirming paid resources.
4. After the first deploy, check the generated `onrender.com` URL. `/api/v1/health/live` checks process
   liveness. The page displays a public-demo warning on every route.

The Render app uses `ENVIRONMENT=production` to hide the development API docs while explicitly enabling
`DEMO_MODE=true`. Keep that distinction: do not set demo mode to false and present this incomplete product as
a real service. The deployment runs database migrations before each deploy. Auth secrets are generated by
Render; do not replace them with development keys.

This demo has no real SMS provider (D-03), payment provider (D-02), or approved pilot/legal operating model
(D-01, D-04, D-06–D-09). Those decisions and the incomplete phases listed in `docs/architecture/architecture.md`
must be resolved and implemented before accepting real participants or prizes.
